# イベント別売上

管理画面 `/admin/events` でイベント名・開始日・終了日を登録する。日本時間の両日を含む期間で新しい売上を分類する。対象なしは未設定。過去の売上は再分類しない。イベント名は売上作成時のスナップショットを保存する。

登録・一覧・停止に対応し、編集/削除は提供しない。停止済みイベントへの新規紐づけはなく、過去の売上・名前・集計は維持する。停止イベントは期間重複判定から除外する。誤登録や複数インスタンスの競合で重複した場合は停止して復旧できる。売上額・件数は保存完了かつ取消されていない取引のみ集計。取引履歴でイベント/未設定に絞り込める。

## 安全なシート移行（デプロイ前）

1. Spreadsheetのバックアップ/変更履歴を確認。
2. `events` タブがなければ作成。A1:F1=`event_id,name,start_date,end_date,created_at,status`。既存の場合は照合し、別用途なら中止。旧5列の場合F列が空であることを確認してF1のみstatusを追記する。既存のstatus空欄はactive扱い。
3. `sales` A:O は変更しない。P:Q が空か正しい追加列であることを確認し P1=`event_id`、Q1=`event_name_snapshot`。別データなら中止。
4. 過去売上P/Qは空欄のまま。旧15列レコードも読めるが、未移行シートへの新規売上は拒否する。
5. 本番取引を作らずヘッダ・一覧・既存売上の読込みを確認する。

## APIと制約

イベントは停止済みを含め999件まで（ヘッダを含む読込み範囲A1:F1000）。上限では新規作成を拒否する。

- GET `/api/admin/events`: 管理セッション必須。`data.events` にイベント＋`saleCount,totalYen`。
- POST 同URL: 管理セッション＋同一Origin必須。`{name,startDate,endDate}`。名前1〜80文字、実在日付YYYY-MM-DD、開始≦終了、重複日なし。
- GET `/api/admin/sales?eventId=UUID` / `eventId=none`: 履歴絞込み。
- PATCH `/api/admin/events/[eventId]`: 管理セッション＋同一Origin、`{status:"archived"}` のみ。イベントの停止。

Sheetsにはトランザクション/一意制約がない。登録は同一プロセス内で直列化するが、複数インスタンス間は排他できないためイベント管理者1名が順次操作する。直接シート編集や競合で重複期間ができた場合は売上作成時に拒否し、誤紐づけを防ぐ。登録タイムアウト後は一覧を確認してから再試行する。

イベント作成はevents行とGoogleの変更履歴を記録とし、現バージョンではaudit_logsへの二重書込みは行わない（別書込み失敗で登録済みイベントを失敗と誤認させないため）。

`challenge_enabled=false` で作成した売上は購入スタンプ1個・`skipped` を保存。設定変更で既存取引を書き換えない。
