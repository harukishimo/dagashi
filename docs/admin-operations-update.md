# 商品検索・運用設定・購入者属性

## 商品マスタ

登録済み一覧で、商品名の部分一致、販売価格の選択、ステータスの複数選択を組み合わせる。
商品名は全角半角・大文字小文字・ひらがなカタカナを吸収する部分一致検索。
ステータスは未選択ですべて、複数選択時は選んだいずれかに一致する商品を抽出する。
初期表示は販売価格の安い順。同価格は表示順・名前・商品IDで順序を安定させる。
「表示順」で `display_order` 順に切り替えられる。一覧の検索・並び替えは保存データや子ども画面の順序を変更しない。

### 在庫の一括編集

1. 会計を一時停止し、「商品マスタ」の「在庫を一括編集」を押す。最新の在庫を読み込み、全商品の現在庫が入力欄になる。
2. いま実際にある個数を入力する。0は在庫切れ、空欄は在庫管理なし。入荷数ではなく、入荷後の合計個数を入れる。
3. 「在庫を一括保存」で変更した商品だけをまとめて保存する。「キャンセル」では変更を保存しない。

編集中も検索・絞り込みができる。絞り込みで隠れた商品の変更も保存対象に含まれる。
保存時は商品名・価格・画像・状態を変更せず、在庫と更新日時だけを更新する。
編集開始後に対象商品の在庫や商品情報が変わっていた場合は、全件の保存を中止する。入力内容を確認したうえで、一括編集を閉じ、最新の在庫を読み直して再入力する。
通信エラーで保存結果が不明な場合も、連打せず最新の在庫を確認する。

Google Sheetsには比較と更新を一体化した排他制御がないため、別のサーバーやシート直接編集との同時更新を完全には防げない。棚卸し・一括保存中は会計とシートの直接編集を止める。

## 設定・接続

10秒チャレンジ設定の下に次の設定を追加。変更は1項目ずつ保存する。

- 取引登録前のPIN確認：初期値オン。オフのときもスタッフが支払確認後に売上登録する。管理画面へのログインは常に認証が必要。
- 子ども画面の商品表示：「通常の一覧」（初期値）と「価格別にグループ表示」。同じ販売価格の商品をまとめ、安い価格から表示する。各グループ内は表示順。グループごとの淡い背景色と「10円のおかし」などの価格見出しで区別できる。価格別表示では左側に価格メニューが現れ、押すと該当の価格帯へ移動し、現在見ている価格帯が強調表示される。画面幅が狭い場合は左上の「ねだんメニュー」で開く。通常の一覧では価格メニューを表示しない。画面を開き直して反映する。設定値は `flat` / `price`。以前の `category` 設定は読み取り時に価格別表示として扱う。
- 購入者属性のアンケート：初期値オフ。オンの場合は商品選択画面の上部と会計画面で親子・子どものみ・大人のみ・未登録をラジオボタンで選択できる。どちらの画面でも変更でき、同じタブで商品選択・かご・会計を行き来しても回答を引き継ぐ。選択は任意。未回答や設定オフは未登録として保存。購入完了後は次のお客さまへ回答を引き継がない。

## 結果

取引履歴に購入者属性の件数・構成率・売上金額を表示する。イベント選択に連動する。
確定済み・未取消の取引だけを集計し、未登録を含む件数を分母とする。
過去の売上と手入力売上は未登録。手入力は1商品明細を1件として数える。
保存後にアンケートをオフにしても過去の回答は維持し、取消は集計から除外する。

## 初回移行

環境変数設定後、管理担当者1名で実行する。

```sh
node scripts/migrate-operations.mjs
node scripts/migrate-operations.mjs --apply
```

1行目は確認のみ。2行目は不足する `settings` の3行と `sales!R1` の `customer_type` 見出しを追加する。売上シートがQ列までの場合は空のR列も追加する。
既存の設定値・売上・在庫は変更しない。すでに移行済みなら変更なし。想定外の見出し・R列の使用・重複設定がある場合は中止する。
売上は既存の15列・17列も読める。新しい売上登録には18列の移行が必要。
購入者属性は `family` / `children` / `adults` / `unregistered` として保存する。

PINオフのときに作成した売上も、同一リクエストIDによる照合・再試行で二重計上を避ける。
