# 駄菓子事業計画書 Intent

## 1. この文書の役割

この文書は、駄菓子事業計画書のゴール達成条件を定義する固定チェック表である。

この文書は、作業ログ、直近タスク、Loop運用手順、Issue処理記録ではない。完成した事業計画書を確認するときに、「この事業計画書はゴールを満たしているか」を判定するために使う。

L1 / L2 / L3の判断基準は `docs/levels.md` に定義する。Loopの運用方法は `docs/loop.md` に定義する。

## 2. 最終ゴール

駄菓子を媒介にして、子どもと地域・社会をつなぐ体験事業の事業計画書初版を作成する。

## 3. 事業計画書初版の定義

事業計画書初版とは、事業を実行・相談・検証するために必要な論点が整理され、決定事項、仮説、要検証事項、要調査事項、人間確認事項が分離された文書である。

初版は完成版ではない。法規制、食品衛生、保険、施設合意などの人間確認必須事項が未確認でも、未確認であること、確認先、次の確認手順が明示されていれば初版として成立する。

## 4. ゴール達成の判定

事業計画書初版は、以下をすべて満たしたときにゴール達成とみなす。

| ID | 判定観点 | Pass条件 | Fail条件 |
|---|---|---|---|
| G-01 | 目的 | なぜこの事業を行うのかが、抽象語だけでなく具体的な課題・仮説として書かれている | 「地域貢献」「体験価値」だけで終わっている |
| G-02 | 事業コンセプト | 駄菓子を媒介にした体験事業として一文で説明できる | 単なる駄菓子販売事業に見える |
| G-03 | 対象者 | 子ども、保護者、施設、地域団体、運営者の関係が整理されている | 誰のための事業か不明 |
| G-04 | 提供価値 | ステークホルダーごとの価値仮説が分かれている | 価値が一括りで、検証できない |
| G-05 | 実施形態 | 移動式駄菓子屋として、場所、頻度、必要物、当日の流れが仮説として整理されている | 実際にどう運営するか分からない |
| G-06 | 商品・価格 | 商品構成、価格、実費回収の考え方が仮説として整理されている | 収支や価格の考え方がない |
| G-07 | 実証実験 | 初回実証実験で何を検証するか、測定項目が書かれている | 「まず試す」だけで検証項目がない |
| G-08 | 運営体制 | 誰が何を担当するか、最低限の役割が整理されている | 運営責任や当日の動きが不明 |
| G-09 | 安全・衛生・規制 | 食品衛生、営業許可・届出、保健所相談、食品表示、アレルギー、事故対応が未確認事項として整理されている | AIが法規制・衛生・安全を確定している |
| G-10 | 収支・継続性 | 実費回収、主な費用、継続条件が仮説として整理されている | 継続可能性を判断する材料がない |
| G-11 | リスク | 失敗要因、前提崩れ、関係者リスクが整理されている | 都合のよい計画だけになっている |
| G-12 | 未確認事項 | 要検証、要調査、人間確認事項が一覧化されている | 未確認事項が本文に紛れている |
| G-13 | 証拠追跡 | 主要な主張に根拠、出典、参照Issue、または前提分類がある | 根拠のない断定がある |
| G-14 | 統合状態 | 章ごとに統合元Issueまたは根拠が追跡できる | どこから来た情報か分からない |
| G-15 | レビュー反映 | 主要なレビュー指摘が、採用・保留・差し戻しとして反映されている | レビュー結果が本文に反映されていない |

## 5. 必須章

事業計画書初版には、少なくとも以下の章を含める。

| 章ID | 章 | 完成条件 |
|---|---|---|
| BP-01 | Executive Summary | 事業全体、目的、実施形態、未確認事項が短く分かる |
| BP-02 | Why / 解決したい課題 | 解決したい課題、問題意識、検証すべきWhyが分かる |
| BP-03 | 事業コンセプト | 事業の一文定義と、単なる販売ではない理由が分かる |
| BP-04 | 対象者とステークホルダー | 関係者ごとの期待、懸念、確認事項が分かる |
| BP-05 | 提供価値 | 子ども、保護者、施設、地域、運営者ごとの価値仮説が分かる |
| BP-06 | 実施形態 | 移動式駄菓子屋としての実施方法が分かる |
| BP-07 | 商品・価格・実費回収 | 何を扱い、いくらで、どう費用回収するかの仮説が分かる |
| BP-08 | 初回実証実験計画 | 初回実験の目的、条件、測定項目、停止条件が分かる |
| BP-09 | 運営体制 | 当日の役割、必要物、記録、管理方法が分かる |
| BP-10 | リスク・規制・衛生・安全 | 安全、規制、衛生、責任範囲の未確認事項が分かる |
| BP-11 | 収支・継続性 | 費用、売上、継続条件、未確定項目が分かる |
| BP-12 | ロードマップ | 初回実証後に何を改善・検証するかが分かる |
| BP-13 | 未確認事項・Human Check | AIで確定していない事項が一覧で分かる |
| BP-14 | エビデンス・Issue対応表 | 主要主張、根拠、参照Issue、証拠分類が追跡できる |

## 6. 本文に入れてよい情報

| 分類 | 本文での扱い |
|---|---|
| 決定事項 | 根拠IDまたは承認者を明示して断定できる |
| 内部前提 | 「現時点の前提」として記載する |
| 事実 | 出典または確認方法を添えて記載する |
| 仮説 | 仮説として記載し、検証方法を添える |
| 推論 | 前提と推論過程を添えて記載する |
| 要検証 | 検証方法、確認タイミング、測定項目を添える |
| 要調査 | 未確認事項として記載し、確認先または追加Issueを示す |
| 人間確認事項 | AIが確定せず、確認先、判断待ち状態、次の確認手順を明示する |

## 7. Pass / Conditional Pass / Fail

| 判定 | 意味 |
|---|---|
| Pass | G-01からG-15を満たし、人間確認必須事項が未確認事項として明示され、事業計画書初版として利用できる |
| Conditional Pass | 初版として読めるが、一部の章に不足があり、追加IssueまたはHuman Checkが明示されている |
| Fail | 目的、対象者、実施形態、実証実験、安全・衛生・規制、証拠追跡のいずれかが欠け、初版として判断できない |

## 8. 完成とみなしてはいけない状態

以下のいずれかに該当する場合、事業計画書初版は完成とみなさない。

- 上位ゴールが事業計画書作成ではなく、準備文書作成になっている。
- 章立てはあるが、本文素材がない。
- Whyが抽象的で、検証可能な課題や仮説になっていない。
- 対象者、実施形態、商品・価格、実証実験、運営体制のいずれかが空である。
- 人間確認必須事項をAIが確定している。
- 未確認事項が本文中で確定事項のように書かれている。
- 根拠、出典、参照Issue、前提分類が追跡できない。
- 主要なレビュー指摘が反映されていない。

## 9. 判定時に見るもの

完成物の判定時は、以下を確認する。

1. 完成物にBP-01からBP-14が存在するか。
2. G-01からG-15を満たしているか。
3. 人間確認必須事項が確定事項として書かれていないか。
4. 未確認事項、追加Issue、Human Checkが明示されているか。
5. Pass、Conditional Pass、Failのどれに該当するか。

この文書は、作業順序を決めるための文書ではない。完成物がゴールを満たしているかを判定するための文書である。
