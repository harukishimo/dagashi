# L1 / L2 / L3 分岐基準

## 1. この文書の役割

この文書は、駄菓子事業計画書作成LoopにおけるL1 / L2 / L3の分岐基準を定義する。

L分類は、論点の重要度ではなく、自動化でどこまで実行するかを決めるための実行モードである。

## 2. Level定義

| Level | 名称 | 起動する役割 | 実行できること | 停止位置 |
|---|---|---|---|---|
| L1 | レポートのみ | Triageのみ | 状態、分類、理由、推奨対応を記録する | 人間判断待ち |
| L2 | アシスト変更 | Triage、Implementer、Verifier | 新規作成、更新、移動、分割、検証、PR作成まで行う | PR作成後に停止。mergeは人間 |
| L3 | 無人実行 | Triage、Implementer、Verifier | denylist外の変更に限り、新規作成、更新、移動、分割、検証、Auto-commitまで行う | Auto-commit後に停止。denylist内は人間キュー |

Verifierは現時点では独立エージェントではなく、Review Agentが兼務する。L2 / L3で変更差分が発生した場合、PR作成前またはAuto-commit前に実差分ベースで `docs/denylist.json` を再確認する。

## 3. L1 - レポートのみ

### 定義

L1は、AIが実装や検証を行わず、Triageだけが状態を書き込むモードである。

Implementer / Verifier は起動しない。すべての判断は人間に委ねる。

### 実行内容

- Issue、資料、差分、章ID、証拠分類を読む。
- 対象タスクの状態を記録する。
- L分類の理由を記録する。
- denylist該当有無を記録する。
- 追加で必要な情報を記録する。
- 人間が次に判断すべき事項を記録する。

### 禁止事項

- Implementerを起動しない。
- Verifierを起動しない。
- 事業計画書成果物としてのファイルを新規作成、更新、移動、削除しない。
- テストを実行して合否判断しない。
- commitしない。
- PRを作成しない。
- mergeしない。
- 事業判断を確定しない。

### L1にする条件

- ユーザー判断が必要である。
- 情報が不足している。
- 仕様、目的、ゴール、章構成の解釈に迷いがある。
- denylistに該当し、人間キューへ上げる必要がある。
- 法規制、衛生、安全、保険、責任、個人情報、子どもに関わる判断が必要である。
- 外部提出、公開、送信、合意形成に関わる。

## 4. L2 - アシスト変更

### 定義

L2は、AIがImplementerとVerifierを起動し、変更と検証を行うモードである。

テストや検証が通過しても、PR作成までで停止する。mergeは人間が行う。

### 実行内容

- Triageが対象、理由、denylist該当有無を記録する。
- Implementerが新規作成、更新、移動、分割などの変更を行う。
- Verifierがテスト、lint、整合性確認、差分確認を行う。
- Verifierが実差分ベースで `docs/denylist.json` を再確認する。
- 検証結果を記録する。
- 必要に応じてcommit、push、PR作成を行う。
- PR作成後に停止し、人間レビューを待つ。

### 禁止事項

- PRをmergeしない。
- 本番反映しない。
- 外部提出、送信、公開をしない。
- 人間確認必須事項を確定しない。
- denylist該当タスクを人間承認なしに処理しない。

### L2にする条件

- 新規ファイル作成、既存ファイル更新、ファイル分割、移動などの変更作業が必要である。
- Implementerによる編集が必要である。
- Verifierによる検証が必要である。
- 人間が最終merge判断を行うべきである。
- 事業計画書本文、調査メモ、要約ファイル、Issueテンプレート、Loop文書、エージェント仕様などに意味のある変更を行う。
- テストやレビューを通してからPR化すべきである。

## 5. L3 - 無人実行

### 定義

L3は、denylistの外にある変更に限り、AIが無人で新規作成、更新、移動、分割、検証、Auto-commitまで実行するモードである。

denylist内の変更はL3で実行しない。人間キューへ昇格する。

### 実行内容

- Triageがdenylistに該当しないことを確認する。
- Implementerが変更する。
- Verifierが検証する。
- Verifierが実差分ベースで `docs/denylist.json` を再確認する。
- 検証通過後、Auto-commitする。
- commit情報、検証結果、差分概要を記録する。

### 禁止事項

- denylistに該当する変更を実行しない。
- 人間確認必須事項を確定しない。
- PRをmergeしない。
- 外部サービスへ公開、送信、共有しない。
- git push、PR作成、Issue closeなど外部副作用を行わない。ただし、別文書でL3の外部副作用が明示的に許可された場合を除く。
- 無関係な未コミット変更を巻き込まない。

### L3にする条件

以下をすべて満たす場合だけL3にできる。

- denylistに該当しない。
- 変更範囲が限定されている。
- 要件が明確である。
- 実装内容が低裁量である。
- 検証方法が明確である。
- Verifierによる検証が通る。
- 実差分ベースのdenylist再確認が通る。
- Auto-commit対象ファイルが明確である。
- 人間判断を必要としない。

## 6. denylist参照

denylist本体は `docs/denylist.json` に定義する。この文書にはdenylist項目を直接列挙しない。

L判定時、Triageは必ず `docs/denylist.json` を確認する。該当項目がある場合、L3無人実行は禁止し、人間キューへ昇格する。

L2ではPR作成まで許可される場合がある。`docs/denylist.json` はL3無人実行の除外リストであり、L2で実行可能かはTriageと人間承認の条件で別途判断する。

## 7. 新規ファイル作成の扱い

新規ファイル作成もL分類の対象である。既存ファイルの修正だけがL分類対象ではない。

| 新規ファイルの種類 | Level |
|---|---|
| Triageが状態、理由、判断待ち事項だけを記録するレポート | L1 |
| 情報を整理したMarkdown、章別本文案、調査メモ、要約ファイル、チェックリスト | L2 |
| 承認済みテンプレートに沿った空ファイル、機械的な対応表、明確な指示に基づく軽微なファイル分割 | L3可 |
| 事業判断、法規制、衛生、安全、価格、外部説明の確定を含む新規ファイル | denylist。人間キュー |
| 外部提出版、営業資料、保護者・施設向け確定文書 | denylist。人間キュー |

新規ファイルを作るだけで自動的にL2になるわけではない。ただし、今回の事業計画書作成で「情報をまとめたファイル」を新規作成する場合は、原則L2として扱う。理由は、内容の取捨選択、構成、表現に判断が含まれ、Verifierと人間レビューが必要になるためである。

## 8. 分岐フロー

```text
1. Triageがタスクを読む
2. docs/denylist.jsonを確認し、denylistに該当するか確認する
   - 該当する: L3禁止。人間キューへ昇格。必要に応じてL1またはL2として扱う
   - 該当しない: 次へ進む
3. 実装や検証を行わず、人間判断だけが必要か確認する
   - はい: L1
   - いいえ: 次へ進む
4. 新規作成・更新・移動・分割などの変更をPR作成までAIに任せ、人間がmerge判断すべきか確認する
   - はい: L2
   - いいえ: 次へ進む
5. denylist外で、Auto-commitまで無人実行できるか確認する
   - はい: L3
   - いいえ: L1またはL2
```

## 9. 章IDとの関係

章IDはL分類を自動決定しない。同じ章でも、処理内容によってL1 / L2 / L3が変わる。

| 章ID | 章 | 分岐の目安 |
|---|---|---|
| BP-01 | Executive Summary | 本文変更はL2。表記修正のみならL3可 |
| BP-02 | Why / 解決したい課題 | 判断待ちはL1、本文案はL2、誤字修正のみL3可 |
| BP-03 | 事業コンセプト | 本文案はL2、最終決定はL1または人間キュー |
| BP-04 | 対象者とステークホルダー | 整理はL1、本文案はL2 |
| BP-05 | 提供価値 | 仮説作成はL2 |
| BP-06 | 実施形態 | 案作成はL2、施設合意や実施可否はL1または人間キュー |
| BP-07 | 商品・価格・実費回収 | 仮説作成はL2、価格確定や食品表示判断はL1または人間キュー |
| BP-08 | 初回実証実験計画 | 計画案はL2、実施決定はL1または人間キュー |
| BP-09 | 運営体制 | 案作成はL2、責任範囲や保険判断はL1または人間キュー |
| BP-10 | リスク・規制・衛生・安全 | 確認項目整理はL1、未確認事項本文案はL2、確定判断は人間キュー |
| BP-11 | 収支・継続性 | 仮説作成はL2、予算確定はL1または人間キュー |
| BP-12 | ロードマップ | 案作成はL2 |
| BP-13 | 未確認事項・Human Check | 一覧化はL1、本文整形はL2、表記修正のみL3可 |
| BP-14 | エビデンス・Issue対応表 | 整理はL1、機械的な表更新のみL3可 |

## 10. 出力テンプレート

```md
## L分類

- Level:
- 起動する役割:
- denylist該当:
- denylist_source: docs/denylist.json
- 判断理由:
- 実行できること:
- 変更種別: 新規作成 / 更新 / 移動 / 分割 / 削除 / なし
- 停止位置:
- 人間キューへの昇格要否:
- PR作成可否:
- Auto-commit可否:
```
