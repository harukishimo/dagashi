# 商品画像による Sheets 読み取り増幅の修正

2026-09-18

## 調査

本番 `/api/products` の429報告に対し、調査時の単発GETは200だった。Google側の実際のクォータログは取得していないため、当該429の発生源の完全な確証はない。
ただし画像APIが `findById -> listAll` を経由し、画像1枚につき products、stock_total、sales、sale_items、reward_redemptions の5回のSheets読み取りを行う不具合を確認した。18枚なら最大90回（再試行を除く）となり、商品一覧取得の分も加算される。

Googleの標準読み取り上限は1ユーザー・1プロジェクトあたり毎分60回。サービスアカウントは1アカウントとして扱われる。
出典: https://developers.google.com/workspace/sheets/api/limits

## 修正

- 画像専用の商品検索では商品マスターA:Kのみ読み、在庫台帳を読まない。
- 画像用マスターは同一プロセス・スプレッドシートごとに30秒キャッシュし、並行リクエストを統合。失敗は保存しない。
- キャッシュは最大64スプレッドシートに制限。Vercelの別インスタンス間の共有は保証しない。
- 会計・商品一覧・管理操作の在庫確認はキャッシュしない。直接シート編集の画像情報は最大30秒遅れて反映される（画像の既存ブラウザキャッシュは別）。
- Sheetsの再試行間隔を100/200msから1/2秒＋ジッターへ変更。
- 商品APIの429にはRetry-After:60とno-storeを返す。

## 検証

- 18件の並行画像検索がSheets読み取り1回になる回帰テスト。
- TTL、シート間分離、失敗後の再取得、通常読み取りがキャッシュされないことを検証。
- 単体・結合テスト107件、Lint、型チェック成功。
- 高負荷をかけて本番の制限を再現するテストは実施しない。
