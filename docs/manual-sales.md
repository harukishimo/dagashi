# 障害時の手入力売上

[手入力売上シート](https://docs.google.com/spreadsheets/d/1yhO3cx1ESXCW9MTmHTKGixLR_fuyD7KFEyNW6Fs3xM8/edit?gid=1007#gid=1007)

## 入力手順

1. 新しい空行を使い、状態を「下書き」にする。記録IDは用意済みのものを使い、コピー・変更しない。
2. 売上日時を日本時間で `2026-09-18 12:00:00` の形式で入力する。
3. 商品セルの▼から商品名を選択する。末尾の `[商品ID]` は識別用で、手入力不要。
4. 実際の販売単価と数量を入力する。合計金額は自動計算される。
5. 内容を確認して状態を「確定」にする。アプリ側は画面再読み込み後に集計する。

サンプル行（カルパス15円×2個＝30円）は集計対象外。実売上に変更しないでください。
「取消」にすると売上・販売数量・在庫消費の対象外になります。修正は一旦「下書き」に戻してから行ってください。

## 集計仕様

- `sales` / `sale_items` には転記しない。読み取り時に手入力行を仮想明細として合算し、二重転記を防ぐ。
- 売上、商品別内訳・構成率、イベント別売上、在庫消費に反映。1行＝1商品明細を1件として数える（複数商品の同一会計を束ねる機能はない）。
- イベントは売上日時（日本時間）と有効なイベント期間から読み取り時に判定。イベント期間の変更・アーカイブで手入力分の所属は再判定される。
- 同じ記録IDの確定行が複数ある場合や、確定行が不正な場合は集計を停止する。対象行を下書きに戻して修正する。
- 同じ実売上を別IDで再入力した場合までは自動判定できない。アプリで登録済み・保存結果不明の会計は、取引履歴を確認してから入力する。
- 1000行まで対応。用意済み行を使う。商品候補は `products` の1000行目まで自動追従する。
- 単価は0〜999999円、数量は1〜9999の整数、1行の合計は999999999円以下。
- 在庫数そのものは上書きせず、手入力の販売数量も台帳から差し引く。販売済み事実を記録するため、在庫不足を理由に手入力売上を拒否しない。
- 支払方法は未指定のため「その他」。スタンプやチャレンジは追加しない。
- Sheetsそのものが使用不能なときは紙などに控え、復旧後に入力する。未入力の間、アプリはその在庫消費を知ることができない。

## 導入

アプリ更新と、同じ接続先スプレッドシートへの「手入力売上」「手入力商品リスト」追加が必要。
本番利用にはアプリのデプロイが必要。シートだけ追加しても旧バージョンは手入力を集計しない。
