# 駄菓子 おかいもの体験アプリ コーディング実行プロンプト

## 1. 使い方

以下の「実行用プロンプト」全体を、リポジトリのルートを作業ディレクトリとしてコーディングエージェントへ渡す。

このプロンプトのゴールは、計画や雛形の作成ではなく、アプリをローカルで起動・操作できる状態、または不足している秘密の環境変数を設定すれば起動できる状態まで実装を完走させることである。

AG-00は次を必ず実行してください。

1. チケット開始前に、担当エージェント、依存チケット、所有ファイル、期待出力、テストを明示して委任する。
2. 実装エージェントへ「他のエージェントも同じリポジトリで作業しているため、他者の変更を巻き戻さず、競合時は調整すること」を伝える。
3. 同じファイルを複数エージェントへ同時に割り当てない。
4. 依存関係がなく所有ファイルが重ならないチケットだけを並行実行する。
5. エージェントの提出物を受け取ったら、AG-00自身が差分、テスト結果、仕様適合を確認してから統合する。
6. 実装担当とは別のエージェントをRV-REDとして起動する。
7. Redの出力後、別のRV-BLUEへ差分、Implementation Handoff、全Red Findingを渡す。
8. RedとBlueの出力がそろった後、別のRV-PURPLEへ最終判定を依頼する。
9. PurpleがCHANGES REQUESTEDを出した場合、元の実装担当へFinding ID付きで差し戻し、修正後に独立レビューを再実行する。
10. エージェントが失敗・停止した場合は、原因を確認して同じ担当へ追加指示するか再割当する。便宜上AG-00が全実装を引き取ってレビュー工程を省略しない。
11. 利用可能な同時実行枠が少ない場合は順番に起動する。枠不足を理由に専門エージェントを省略しない。

環境変数とローカル実行
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

次の環境変数をサーバー側の検証スキーマで管理し、`.env.example`へ秘密値なしで記載してください。

- GOOGLE_SPREADSHEET_ID

- GOOGLE_CLIENT_EMAIL
- GOOGLE_PRIVATE_KEY
- ADMIN_PIN_HASH
- SESSION_SECRET
- APP_TIMEZONE

要件:

- `.env.local`、秘密鍵、実PIN、実Cookieをコミットしない。
- `GOOGLE_PRIVATE_KEY`の改行形式を安全に正規化する。
- Application Default Credentials等を利用できる場合は長期鍵より優先できる構造にする。
- 不足・不正な環境変数を起動時または対象サーバー機能の初期化時に明確なエラーとして検出する。
- エラー画面や公開healthへ秘密値・Spreadsheet ID・Drive file_idを返さない。
- READMEへサービスアカウント共有、PINハッシュ生成、SESSION_SECRET生成、秘密鍵の設定方法を書く。
- テストではproduction検証を無効化せず、テスト専用環境値とモックを明示的に注入する。

ローカル起動手順は、最低限次の形で再現可能にしてください。実際に選んだpackage managerへコマンドを統一してください。

1. 対応Node.js LTSを確認する。
2. 依存関係をlockfileどおりインストールする。
3. `.env.example`を基に`.env.local`を作成する。
4. 必要なGoogle権限を設定する。
5. 開発サーバーを起動する。
6. 公開health、商品一覧、管理ログインを確認する。
7. 型、Lint、単体、結合、E2E、buildを実行する。

Node.jsとpackage managerのバージョンはリポジトリへ固定し、READMEと実行環境で一致させてください。
